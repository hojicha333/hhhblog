# 路线图与边界

## 首版已完成

- 四栏目静态内容系统与极简 Markdown 发布
- 编辑型首页、栏目页、两种详情页、归档与 About
- Pagefind 全文搜索、随机漫游、RSS、sitemap 和 SEO 元数据
- 深浅主题、响应式布局、键盘导航与减少动态偏好
- 静态图片优化、构建检查、备份与部署说明

## 正式发布前

这些工作需要真实内容或账号信息，适合在本地视觉方向确认后完成：

1. 用 3 至 6 篇真实内容替换最有代表性的示例稿。
2. 替换示例照片，补齐项目截图、研究图和准确替代文字。
3. 确定 About 中的网名介绍、联系方式和必要的现实身份信息。
4. 选择域名，建立私有仓库，连接 Cloudflare Pages。
5. 生成专属社交分享图，检查中文与英文链接预览。
6. 对真实内容做一次隐私、事实、死链与素材授权检查。

## 内容积累后再做

只有真实使用证明需要时才实现：

- 标签聚合页与人工专题 / 系列页
- 文内双向链接与“被哪些文章提到”
- 阅读、收听或观看记录
- 独立小工具入口与在线演示
- 英文界面或真正的双语文章映射
- 自动生成社交分享图
- 内容量达到约 50 篇后的搜索筛选和人工索引

这些功能可以继续建立在当前 Markdown 与静态路由上，不需要更换框架。

## 暂缓

- 评论与账户系统
- 数据库和动态 CMS
- 实时 VPS / 服务状态
- 自动抓取社交平台与音乐状态
- 访问分析和营销追踪
- 环境音播放器
- 为中国大陆访问提前建设双站、备案或 VPS 后端

暂缓的原因不是技术上无法实现，而是它们会引入隐私、授权、运行成本或持续维护义务。在出现具体内容需求前，不把可能性变成固定负担。

## 重新评估的信号

出现以下情况时再讨论架构扩展：

- 需要访问者提交数据、登录或保存个人状态
- 一个真实工具必须在服务器端处理任务
- 内容团队扩大到无法继续通过 Git 协作
- 中国大陆稳定访问成为明确且持续的目标
- 访问数据将直接支持一个具体编辑或产品决策

即使增加动态能力，也优先把它作为独立服务接入；正文、页面与静态导出继续保持可独立运行。
